ADK Orchestration

What each agent does for common food questions.

The orchestrator uses semantic meaning, keywords, and recent session context, so “show their addresses” applies to the previous restaurant list instead of becoming a menu search.

Orchestrator agent

Common question: “Show Italian restaurants near Kirkland and their addresses.”

How it works: reads intent, context, and entities, then delegates to the right specialist. It prevents address questions from being treated as menu item searches.

Intent agent

Common question: “Find Thai dinner under $25 near Bellevue for 2 people.”

How it works: extracts cuisine, location, meal, dish, budget, quantity, and constraints before other agents call tools.

Discovery agent

Common questions: “How many Indian restaurants do you have?” “Show restaurants with menus.”

How it works: calls restaurant list, count, genre summary, and detail tools using cuisine, distance, rating, and menu coverage filters.

Menu agent

Common questions: “Show Taste of India menu.” “What appetizers does Kin Dee Thai have?”

How it works: finds the matched restaurant, retrieves ingested menu rows, filters sections, and uses hybrid search for dish names.

Pricing agent

Common questions: “Compare Pad Thai prices near Bothell.” “Cheapest chicken tikka masala near Seattle?”

How it works: compares exact and normalized menu item matches, filters irrelevant charges, and returns competitive price tables.

Review and ranking agents

Common question: “Recommend Thai restaurants with good reviews and reasonable prices.”

How it works: summarizes review signals, combines distance, rating, menu coverage, price, and constraints, then ranks recommendations.

Ingestion

Real restaurant data needs several ingestion paths.

Direct scraping alone is not reliable, so the pipeline combines discovery, browser rendering, link inspection, manual URLs, curated menu rows, and embeddings.
